# Проверка Android через ADB — 3 ноября 2026

Устройство: Huawei ANG-LX1, Android 10, USB ADB. Установлен `io.github.feg55.zarp.debug` через `adb install -r`; основная версия приложения не заменяется.

## Поиск

- Основная кнопка после очистки только тестовых результатов подтвердила `warp-q-google6` двумя независимыми проверками и сразу подключилась. В результатах ровно одна подтверждённая стратегия. Подключение постоянного туннеля: 144 мс, пинг 131 мс; VPN-сервис работал в foreground.
- Нажатие «Быстрый поиск» подтвердило ровно три стратегии: `warp-q-google6`, `warp-q-google3`, `warp-q-vk6`. Выбран `warp-q-google3` по оценке, а не первый кандидат. Подключение: 165 мс, пинг 129 мс.
- Запущенный полный поиск отменён удалением карточки приложения из недавних. Сервис проверки остановился, процесс приложения оставался жив, новый поиск не запускался. Повторное открытие показало «Отключено / Отменено».
- На итоговой сборке повторены отмена основной кнопкой и последующее подключение. Работающий VPN сохранился после удаления карточки; поиск после удаления карточки оставался отменённым в течение 22 секунд наблюдения. PID во всём сценарии не менялся, новых исключений в crash buffer нет.

## Найденное падение сервиса

Короткая операция могла вызвать `Context.startForegroundService() did not then call Service.startForeground()`: завершение приходило раньше обработки команды запуска сервиса. Это воспроизведено на телефоне при завершении неудачной попытки Xray.

Исправление в `ScanKeepAliveService`: операция ждёт подтверждения `startForeground`; даже отменённый запуск сначала выполняет этот контракт Android; остановка ждёт уничтожения сервиса перед следующим запуском. Блокировка движка удерживается во время подтверждения запуска, включая отмену. Убрана остановка ещё не созданного сервиса через `stopService`.

После исправления выполнено 15 быстрых операций запуска/остановки. PID сохранился, foreground-сервисы не остались, новых исключений в crash buffer этого процесса нет.

## Xray/XHTTP

Использован официальный локальный Xray v26.9.30 с временным TLS-сертификатом и подключением телефона через ADB reverse. Пользовательские серверы и подписки для этого не менялись. HTTPS проверяло отдельное приложение с собственным UID, включённое в тестовый VPN.

- Исправная ссылка передаёт HTTPS-трафик; Direct проходит, Block не проходит. Все три соединения с сервером получили TLS split, чужих соединений нет.
- После остановки только тестового Xray-сервера первый сбой сохраняет VPN, второй запускает восстановление и очищает старую цепочку.
- После включения сервера восстанавливается та же пара; HTTPS, Direct и Block проверены повторно.
- При постоянной недоступности сервера выполнены ровно три новые попытки: счётчик постоянных туннелей увеличился с 3 до 6. Затем состояние `Error`, активной пары и VPN нет. Дополнительные проверки не увеличивают счётчик и не запускают поиск.
- Ссылка с неверным pin сертификата отклоняется, активный VPN не создаётся.

Для повторения сценариев добавлены debug-команда `verify-observe`, счётчик `persistentOpens` в приватном результате проверки и сигналы `pause-xray` / `xray-paused` в ручном Go-стенде. Эти средства не входят в release-интерфейс.
