# Поиск стратегий и восстановление Android

Перенесено поведение основной кнопки из Windows `c9b46a6` / `c19709a7`.

- Основная кнопка: сохранённая стратегия, подтверждённые альтернативы, затем перебор до первой стратегии, которая прошла две проверки и действительно подключилась. Неудачная повторная проверка или подключение продолжает перебор.
- «Быстрый поиск»: прежний лимит, по умолчанию три подтверждённые стратегии, с выбором по оценке. Полный поиск проверяет весь набор. В обоих случаях учитываются только результаты, подтверждённые текущим поиском; старый результат непроверенной стратегии не определяет победителя.
- Фоновая проверка: один сбой не перезапускает туннель; два последовательных сбоя при доступном Интернете запускают восстановление текущей стратегии. Максимум три попытки, каждая ограничена 15 секундами, с паузой перед повторением. После исчерпания попыток требуется ручное действие. Сохранённые результаты не помечаются нерабочими, новые стратегии в фоне не перебираются.
- Без Интернета сохраняется нативное переподключение WARP. Успешная проверка сбрасывает счётчик ошибок. Обнаруженный сторонний VPN останавливает фоновое восстановление.
- Завершение Activity или удаление задачи из недавних приложений отменяет текущие проверки и ожидающее восстановление. Работающий VPN сохраняется. Сворачивание и смена ориентации поиск не отменяют.
- Отмена до запуска корутины освобождает блокировку и не стирает ещё не загруженные результаты. Уведомления старого туннеля и запоздалые проверки не изменяют новое подключение. Неожиданное уничтожение VPN-сервиса закрывает оставшийся туннель.
- Короткая операция дожидается подтверждения foreground-запуска и уничтожения сервиса. Исправлено реальное падение Android 10, когда поиск или попытка восстановления завершались до регистрации foreground-сервиса.

## Xray

Android использует Xray внутри процесса, поэтому отдельного `xray.exe`, Windows-адаптера и обработчика завершения дочернего процесса здесь нет. Общая проблема потери работоспособности цепочки устранена ограниченным восстановлением той же пары без нового поиска.

Добавлены проверки настоящего XHTTP-соединения на loopback: закрытие только моста приводит к отказу трафика; закрытие всей цепочки освобождает слушающие порты; повторное создание той же пары восстанавливает трафик; ошибка запуска sing-box после запуска Xray удаляет регистрацию моста. JVM-тест проверяет очистку VPN и туннеля после отказа XHTTP и предел попыток восстановления. Radmin не проверялся.

## Проверка

- JVM: 121 тест, без ошибок и пропусков. Регрессионные проверки основной кнопки, прежней квоты быстрого поиска WARP и серверных пар, неудачного применения, отмены, закрытия UI, старых callback и ограниченного восстановления, включая таймаут зависшей попытки.
- `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug --offline -x buildGoCore`: используется существующий AAR, поскольку код Go-ядра не менялся.
- `go test -tags=with_quic,with_utls,http2legacy ./zarpcore -count=1 -timeout=5m`: в том числе локальные проверки с официальным Xray v26.9.30.
- Сборка APK и Go-тесты прошли; lint: ноль ошибок, три прежних предупреждения (`OldTargetApi`, `ChromeOsAbiSupport`, `ObsoleteSdkInt`). APK: `app/build/outputs/apk/debug/app-debug.apk`.
- Проведена [проверка через ADB на Huawei ANG-LX1, Android 10](android-device-strategy-check.md): поиск, отмена, жизненный цикл VPN и настоящий Xray/XHTTP. Проверка выявила и позволила исправить падение foreground-сервиса при коротких операциях.
