# Проверка новой регистрации WARP на телефоне

25 октября 2026 года, Huawei ANG-LX1, Android 10, USB ADB, текущая Wi-Fi-сеть. Проверена реальная регистрация Cloudflare с новым устройством и ключом MASQUE. Исходный файл аккаунта не изменён: SHA-256 до и после совпадает.

## Результат

| Операция | Результат | Время |
| --- | --- | --- |
| Чтение существующего аккаунта напрямую | Успех | 529 мс |
| Чтение через `split:1,midsld` | Сетевой таймаут | 15 019 мс |
| Чтение через `disorder:1,midsld` | Успех | 597 мс |
| Чтение через `split:1,host` | Сетевой таймаут | 15 017 мс |
| Чтение через `split:1,sld` | Сетевой таймаут | 15 024 мс |
| Чтение через `split:1,endhost` | Сетевой таймаут | 15 017 мс |
| Новая регистрация и enrollment через `disorder:1,midsld` | Успех | 2 026 мс |
| Чтение нового аккаунта напрямую | Успех | 1 015 мс |
| MASQUE/QUIC с новым аккаунтом, `warp-q-google6` | Успех | 704 мс подключения |
| HTTPS `cdn-cgi/trace` через новый туннель | `warp=on` | 174 мс |

Это встроенный TCP desync Android: обычные TCP-сокеты, первый сегмент ClientHello с TTL=1 и последующая доставка через ретрансляцию ядра. Отдельные Windows `winws2`/zapret и WARP-клиент на телефон не скачиваются: Android использует встроенное Go/MASQUE-ядро, а регистрация получает конфигурацию и ключи у Cloudflare.

## Граница проверки

Прямой API в этой сети доступен. Для проверки автоматического перехода `WarpAccountManager` получил искусственную сетевую ошибку только в первоначальной прямой сессии. Затем реальный нативный API-клиент выполнил новую регистрацию и enrollment с TCP desync; прямое создание тестового аккаунта не запускалось. Рабочая стратегия была выбрана первой по результатам предварительных запросов чтения.

Никакие ответы Cloudflare, конфигурация или проверка трафика не подменялись. Тест подтверждает работу защищённой регистрации и автоперехода при заданной ошибке. Блокировка прямого API реальным провайдером не воспроизводилась. Четыре split-стратегии в этой сети не сработали; результат не распространяется на другие сети.

Созданный тестовый аккаунт хранится отдельно в приватных данных debug-приложения, чтобы повторный запуск проверки не создавал лишние устройства. Его ID, токен и ключи не экспортируются в отчёт. Незавершённого enrollment после успешной регистрации нет. Тестовый туннель и foreground service остановлены; экран продолжает оставаться включённым при питании по USB.

## Повторный запуск

Команда доступна только в debug APK отправителю с `android.permission.DUMP`, когда приложение не подключено к VPN и не выполняет другую операцию:

```text
adb shell am broadcast -a io.github.feg55.zarp.DEBUG -n io.github.feg55.zarp.debug/io.github.feg55.zarp.DebugCommandReceiver --es cmd registration-verify
adb shell run-as io.github.feg55.zarp.debug cat cache/warp-registration-result.json
```

Отмена: та же broadcast-команда с `--es cmd registration-stop`. Повторный запуск использует уже созданный тестовый аккаунт и отмечает это в отчёте; исходный аккаунт приложения не сбрасывается. Сохранённый обезличенный результат первого запуска: локальный `build/warp-registration-result.json`.
